# 블렌더 작업 방법 — Mixamo FBX를 캐릭터 glb로

AgentCommander의 3D 캐릭터 에셋을 만드는 절차. Mixamo에서 받은 FBX 여러 개를 **애니메이션 클립이 여러 개 들어 있는 `.glb` 파일 하나**로 합치는 것이 목표다.

---

> ## ⚡ 손으로 할 필요 없다
>
> **[`tools/asset.py`](../tools/README.md)가 이 문서의 2~4장을 전부 대신한다.**
>
> ```bash
> python tools/asset.py add researcher "C:\Users\Ho\Downloads\Typing.fbx"
> python tools/asset.py build researcher
> ```
>
> 블렌더를 창 없이 실행해 임포트·이름변경·NLA 배치·내보내기·검증까지 한 번에 한다. GUI로 하면 슬롯·트랙·내보내기 모드가 얽혀 매번 결과가 달라지는데, 이 도구는 결정적이다.
>
> 아래 수동 절차는 **도구가 실패했을 때 원인을 찾거나, 블렌더에서 직접 손보고 싶을 때** 참고한다. 겪었던 함정들도 그대로 남겨 두었다.

---

> 이 문서는 실제로 한 번 해보면서 겪은 함정까지 담았다. "함정" 절을 먼저 훑고 시작하면 시간을 아낄 수 있다.

---

## 왜 이 작업이 필요한가

Mixamo는 **FBX만** 주고, 웹 3D는 **glTF/GLB**를 쓴다. 게다가 애니메이션을 6종 받으면 **파일이 6개로 흩어져 나온다.** 우리는 파일 하나 안에 클립 6개가 들어 있어야 한다.

```
받은 것                          만들 것
Breathing Idle.fbx  (With Skin)  ─┐
Typing.fbx          (No Skin)    ─┤
Looking Around.fbx  (No Skin)    ─┼─→  researcher.glb  (클립 6개 내장)
Thinking.fbx        (No Skin)    ─┤
Defeated.fbx        (No Skin)    ─┤
Cheering.fbx        (No Skin)    ─┘
```

---

## 1. Mixamo에서 받기

1. `mixamo.com` 로그인 (Adobe 계정, 무료)
2. **`Characters` 탭에서 캐릭터를 먼저 고른다** — 이걸 건너뛰면 기본 마네킹에 적용된다
3. `Animations` 탭에서 애니메이션 검색 → 우측 `DOWNLOAD`

### 다운로드 설정

| 항목 | 값 |
|---|---|
| Format | `FBX Binary(.fbx)` |
| Skin | **첫 번째만 `With Skin`, 나머지는 전부 `Without Skin`** |
| Frames per Second | `30` |
| Keyframe Reduction | `none` |

`Skin` 드롭다운 하나만 바뀌고 나머지는 동일하다. 계속 `With Skin`으로 받으면 파일마다 캐릭터 몸통이 따라와서 블렌더에서 합칠 때 같은 캐릭터가 여러 겹으로 쌓인다.

### 상태별 검색어

| 앱의 상태 | Mixamo 검색어 | 최종 클립 이름 |
|---|---|---|
| `idle` | `Breathing Idle` | `Idle` |
| `running` | `Typing` | `Working` |
| `waiting` | `Looking Around` | `LookAround` |
| `retrying` | `Thinking`, `Head Shake` | `Retry` |
| `error` | `Defeated`, `Dismissing Gesture` | `Alert` |
| `done` | `Cheering`, `Waving` | `Cheer` |

클립 이름이 정확히 이래야 하는 것은 아니다. `frontend/lib/protocol.ts`의 `STATE_CLIP`이 기준이지만, 코드가 부분 일치까지 허용하므로 비슷하면 붙는다.

### 받은 파일이 맞는지 확인

크기로 대략 구분된다. With Skin이 메시(몸통)를 품고 있어 더 크다.

```
Breathing Idle.fbx   2.68 MB   ← With Skin
Typing.fbx           1.53 MB   ← Without Skin
```

## 2. 블렌더에서 합치기

블렌더는 `blender.org/download`에서 받는다(무료). 아래는 한국어 UI 기준이다.

### 2-1. 기본 오브젝트 삭제

블렌더를 켜면 큐브·카메라·조명이 있다. 3D 뷰포트에서 `A`(전체 선택) → `X` → 삭제.

### 2-2. FBX 가져오기

`파일 → 임포트 → FBX (.fbx)`

**반드시 With Skin 파일을 먼저** 가져온다. 그다음 나머지를 하나씩.

가져오고 나면 아웃라이너에 아마튜어가 여러 개 생긴다.

```
Armature       ← With Skin. 메시(Alpha_Joints, Alpha_Surface)가 달려 있다
Armature.001   ← Without Skin. 뼈대만
```

**모든 애니메이션은 결국 `Armature`(메시가 달린 쪽) 하나에 모여야 한다.** glTF는 메시가 붙은 오브젝트 기준으로 애니메이션을 내보내기 때문이다.

### 2-3. 에디터 전환하는 법

화면 아래 영역의 **맨 왼쪽 아이콘 + `▾`** 가 **에디터 유형** 버튼이다.

```
[⚙▾] [액션 에디터 ▾]  뷰  선택  마커  키
 ↑
 이것이 에디터 유형
```

오른쪽의 `액션 에디터` 드롭다운은 **다른 것**이다(도프 시트를 어떤 모드로 볼지 고르는 것). 처음에 헷갈리기 쉬운 자리다.

이 작업에서 오가는 에디터는 둘이다.

- **도프 시트 → 액션 에디터** — 액션을 고르고 이름을 바꾸고 밀어 넣는 곳
- **비선형 애니메이션** — 트랙이 제대로 쌓였는지 확인하는 곳

### 2-4. 액션을 트랙으로 밀어 넣기

각 애니메이션마다 반복한다.

1. 아웃라이너에서 **`Armature`** 선택 (`.001`이 아니라 메시가 달린 쪽)
2. 에디터를 **액션 에디터**로
3. 액션 이름 칸 왼쪽의 **브라우즈 드롭다운**(달리는 사람 아이콘 + `▾`)을 열어 원하는 액션 선택
4. **액션에 실제 데이터가 있는지 확인** — 아래 "빈 액션 걸러내기" 참고
5. 이름을 더블클릭해 위 표의 클립 이름으로 변경 (`Idle`, `Working`, …)
6. 헤더의 **`액션` 메뉴 → `액션을 아래로 밀기`**

```
[⚙▾] [액션 에디터▾]  뷰 선택 마커 채널 키 액션   [🏃▾] Idle [✓] [⧉] [✕]
                                          ↑              ↑
                                    푸시 다운이 여기      브라우즈 드롭다운
```

`액션을 아래로 밀기`가 Push Down의 한국어 번역이다. 툴팁에 "새로운 스트립으로 NLA 스택에 액션을 아래로 밀기"라고 나온다.

밀어 넣으면 액션 이름 칸이 **비어진다. 정상이다** — NLA 트랙으로 내려가면서 연결이 풀린 것이지 없어진 게 아니다.

### 빈 액션 걸러내기 ⚠️

**이름만 맞고 내용이 비어 있는 액션이 섞일 수 있다.** 이걸 밀어 넣으면 트랙은 생기지만 캐릭터가 움직이지 않는다. 내보내기 전까지는 티가 안 나므로 반드시 확인한다.

두 가지 신호로 판별한다.

| 확인할 곳 | 정상 | 비어 있음 |
|---|---|---|
| 액션 에디터 타임라인 | 키프레임(마름모)이 쭉 깔려 있다 | 맨 앞에 한두 개뿐이거나 없다 |
| NLA `활성 스트립` 패널의 프레임 범위 | `1 → 299` 처럼 넓다 | `0 → 1` |
| NLA 스트립 막대 | 타임라인을 가로지른다 | 왼쪽 끝 얇은 조각 |

`0 → 1` 이 보이면 그 액션은 버리고 해당 FBX를 다시 Import해서 새로 들어온 액션을 쓴다.

### 2-5. 확인

에디터를 **비선형 애니메이션**으로 바꾼다. 이렇게 보여야 한다.

```
▼ Armature
    Working  ▬▬▬▬▬▬▬▬
    Idle     ▬▬▬▬▬▬▬▬
```

**트랙이 오브젝트 여러 개에 나뉘어 있으면 잘못된 상태다.**

```
▼ Armature
    Idle     ▬▬▬▬▬▬▬▬
▼ Armature.001          ← 이러면 안 된다
    Working  ▬▬▬▬▬▬▬▬
```

이 경우 `Armature`를 선택한 채로 2-4를 다시 해서 `Working`을 옮긴다. 액션 데이터는 파일 전체에서 공유되므로 어느 오브젝트에서 만들어졌든 갖다 붙일 수 있다. 뼈대 이름이 같기 때문에 그대로 동작한다.

### 2-6. 여분 아마튜어 삭제

**트랙이 전부 `Armature`에 모인 것을 확인한 뒤에** `Armature.001` 등을 아웃라이너에서 선택하고 `X`로 삭제한다.

⚠️ **순서를 지킬 것.** 먼저 지우면 그 아래 있던 트랙도 함께 사라진다.

## 3. 내보내기

`파일 → 내보내기 → glTF 2.0 (.glb/.gltf)`

### 설정

| 항목 | 값 |
|---|---|
| **애니메이션 모드** | **`NLA 트랙`** |
| 경로 | `D:\self_develop\AgentCommand\backend\uploads\` |
| 파일명 | `researcher.glb` (역할별로 `coder.glb`, `reviewer.glb`) |

**`애니메이션 모드`가 핵심이다.** 우측 옵션 패널의 `애니메이션` 섹션에 있는 드롭다운이며, 선택지는 `액션 / 활성 작업 병합 / 생방송 작업 / NLA 트랙 / 씬` 이다. **`NLA 트랙`** 을 고르면 트랙 이름이 그대로 클립 이름이 된다.

> 예전 블렌더의 `Group by NLA Track` 체크박스가 이 드롭다운으로 바뀌었다. 오래된 튜토리얼에는 체크박스로 나온다.

크기가 이상해 보여도 신경 쓰지 않아도 된다. Mixamo는 cm, 블렌더는 m 단위라 100배 차이가 나는데, 앱이 바운딩 박스를 재서 자동으로 맞춘다.

## 4. 검증

내보낸 파일을 반드시 확인한다. **파일이 만들어졌다고 성공한 것이 아니고, 클립 개수만 맞다고 성공한 것도 아니다.** 이름만 있고 내용이 빈 클립이 섞일 수 있으므로 **키프레임 수와 길이까지** 본다.

레포 루트에서 실행한다.

```bash
node -e "const fs=require('fs');const b=fs.readFileSync('backend/uploads/researcher.glb');let o=12,j=null;while(o<b.length){const l=b.readUInt32LE(o),t=b.readUInt32LE(o+4);if(t===0x4E4F534A){j=JSON.parse(b.slice(o+8,o+8+l).toString('utf8'));break}o+=8+l}const acc=j.accessors||[];console.log('클립 '+(j.animations||[]).length+'개');(j.animations||[]).forEach((a,i)=>{let k=0,d=0;a.samplers.forEach(s=>{const x=acc[s.input];if(!x)return;k=Math.max(k,x.count||0);if(x.max&&x.max[0]>d)d=x.max[0]});const n=new Set(a.channels.map(c=>c.target.node)).size;console.log('  '+(i+1)+'. '+JSON.stringify(a.name).padEnd(12)+' 채널 '+String(a.channels.length).padStart(4)+' | 대상본 '+String(n).padStart(3)+' | 키프레임 '+String(k).padStart(4)+' | 길이 '+d.toFixed(2)+'s')});console.log();console.log('본 '+((j.skins||[])[0]?.joints?.length??0)+'개, 메시 '+(j.meshes||[]).length+'개, 루트 '+JSON.stringify((j.scenes[0].nodes||[]).map(n=>j.nodes[n].name)))"
```

**정상 출력**

```
클립 2개
  1. "Idle"       채널  195 | 대상본  65 | 키프레임  300 | 길이 9.97s
  2. "Working"    채널  195 | 대상본  65 | 키프레임  280 | 길이 9.30s

본 65개, 메시 2개, 루트 ["Armature"]
```

**실패 출력** — 클립 개수는 맞지만 두 번째가 비어 있다

```
  2. "Working"    채널  195 | 대상본  65 | 키프레임    2 | 길이 0.03s
                                                      ↑ 껍데기만 들어감
```

키프레임이 한 자릿수이거나 길이가 1초 미만이면 실패다. 2-4의 "빈 액션 걸러내기"로 돌아간다.

### 체크리스트

| 항목 | 기대값 |
|---|---|
| 루트 노드 | `["Armature"]` 하나만 — 여분 아마튜어가 남아 있으면 이름이 더 나온다 |
| 본 | 65개 (Mixamo 표준) |
| 메시 | 1개 이상 — 0이면 With Skin 파일을 안 넣은 것 |
| 클립별 대상본 | 65 — 훨씬 적으면 뼈대가 어긋난 것 |
| 클립별 키프레임 | 수십~수백 |

`@gltf-transform/cli`로 더 자세히 볼 수도 있다.

```bash
npx @gltf-transform/cli inspect backend/uploads/researcher.glb
```

## 5. 앱에 반영

파일을 `backend/uploads/`에 두면 백엔드가 `/models/...`로 정적 서빙하므로 별도 등록이 필요 없다. 역할 이름과 파일명이 맞으면 자동으로 붙는다.

DB의 `model_path`까지 함께 갱신하려면 업로드 API를 쓴다(20MB 제한).

```bash
curl -X POST http://localhost:8000/api/roles/researcher/model -H "x-api-key: local-dev-key" -F "file=@backend/uploads/researcher.glb"
```

앱은 **모델이 없거나 로딩에 실패하면 큐브로 되돌아간다.** 역할별로 따로 판단하므로 셋 중 하나만 준비돼도 그 역할만 캐릭터가 된다.

## 함정 모음

실제로 겪은 것들이다.

**아마튜어가 두 개로 들어온다**
Mixamo FBX를 여러 개 Import하면 흔한 일이다. 반드시 메시가 달린 `Armature` 하나로 액션을 모아야 한다. 2-5 참고.

**여분 아마튜어를 먼저 지웠다**
그 아래 있던 NLA 트랙이 함께 사라진다. 내보낸 파일에 클립이 하나만 들어가는 원인이 대개 이것이다. 반드시 **옮기기 → 확인 → 삭제** 순서로.

**푸시 다운 버튼을 못 찾겠다**
Blender 5.x에서는 헤더 버튼이 아니라 **`액션` 메뉴 안**에 있다(`액션을 아래로 밀기`). `액션` 메뉴는 액션이 할당돼 있을 때만 나타난다.

**`Group by NLA Track` 체크박스가 없다**
`애니메이션 모드` 드롭다운으로 바뀌었다. `NLA 트랙`을 고른다.

**액션 목록에 이름 앞에 `F`가 붙어 있다**
가짜 사용자(Fake User)가 설정됐다는 표시다. FBX Import가 자동으로 붙이며, 덕분에 아마튜어를 지워도 액션 데이터는 살아남는다. 그대로 선택해 쓰면 된다. 앞에 숫자가 붙으면 그 액션을 쓰는 곳의 개수다.

**트랙은 2개인데 내보낸 클립 하나가 비어 있다**
가장 잡기 어려운 함정이다. 이름만 같고 내용이 없는 액션을 밀어 넣은 경우로, 블렌더 화면에서는 트랙이 정상으로 보인다. 4장의 검증 명령으로 **키프레임 수**를 확인해야 드러난다. 밀어 넣기 전에 2-4의 "빈 액션 걸러내기"로 미리 거르는 편이 낫다.

**같은 이름의 액션이 여러 개 생겼다 (`Working`, `Working.001`)**
블렌더는 이름 충돌 시 `.001`을 붙인다. 어느 쪽이 진짜인지 프레임 범위로 구분하고, 가짜는 이름을 바꿔 두거나 지워서 헷갈리지 않게 한다.

**캐릭터가 너무 작거나 크다**
무시해도 된다. 앱이 바운딩 박스를 재서 목표 높이에 맞춘다.

**클립 이름이 표와 다르다**
앱이 부분 일치까지 허용하고, 못 찾으면 첫 클립으로 물러난다. 정확히 맞추면 좋지만 필수는 아니다.

## 작업 시간

처음 한 캐릭터가 1~2시간, 두 번째부터는 20분 정도다. 순서가 몸에 붙으면 반복 작업이다.

**처음에는 클립 2개(`Idle`, `Working`)로만 끝까지 해보길 권한다.** 파일 하나 만들어서 화면에 서는 것까지 확인하면 나머지는 반복이다. 6개를 다 모아놓고 한 번에 시도하면 어디서 틀렸는지 찾기 어렵다.
