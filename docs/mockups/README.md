# UI 목업

화면 설계 초안을 브라우저로 열어볼 수 있는 단일 HTML 파일로 보관한다. 빌드도 서버도 필요 없다 — 파일을 더블클릭하면 열린다.

| 파일 | 내용 | 작성일 |
|---|---|---|
| [`ui-mockup-v1-phase0-5.html`](./ui-mockup-v1-phase0-5.html) | **예상 UI 화면 10장 (v1)** — Phase 0~5. 3D 씬, 대화풍선, 상세 사이드패널, 로그 뷰어, 역할 관리, 실패 상태 | 2026-08-06 |

## v1에 담긴 10장

| # | 화면 | 대응 Phase |
|---|---|---|
| 01 | 배관 확인용 텍스트 화면 | Phase 0 (구현 완료) |
| 02 | 3D 씬 + 큐브 스텁, 상태별 존 | Phase 2 |
| 03 | 리깅 캐릭터 씬 | Phase 3 |
| 04 | 클릭 → 대화풍선 | Phase 4 |
| 05 | 재시도 연출 (running과 시각적 구분) | Phase 4 |
| 06 | 상세 사이드패널 + URL 동기화 | Phase 5 |
| 07 | 상태 패널 오버레이 (목록·진행률) | Phase 5 |
| 08 | 로그 뷰어 (복기) | Phase 5 |
| 09 | 역할 관리 + glTF 업로드 | Phase 5 |
| 10 | 연결 끊김 / 최종 실패 | 전 구간 |

## 읽을 때 주의할 것

- **01번만 실제 화면이다.** 나머지 9장은 명세에서 도출한 예상안이며, 구현하면서 달라질 수 있다.
- **사람 실루엣은 임시 표현이다.** 실제 캐릭터 외형은 Phase 3에서 확보할 glTF 에셋에 따라 결정된다. 목업의 도형은 "여기에 캐릭터가 선다"는 위치 표시일 뿐이다.
- **상태 색 6종은 실제 코드값과 같다.** `frontend/lib/protocol.ts`의 `STATE_COLOR`를 그대로 썼다. 이 값을 바꾸면 목업도 함께 갱신할 것.
- **존 좌표도 실제 코드값과 같다.** `backend/models.py`의 `STATE_ZONES` 기준이다.

## 갱신 규칙

화면 설계가 크게 바뀌면 기존 파일을 덮어쓰지 말고 `ui-mockup-v2-*.html`로 새로 만든다. 어떤 시점에 무엇을 합의했는지가 남아야 나중에 "왜 이렇게 정했더라"를 되짚을 수 있다.
